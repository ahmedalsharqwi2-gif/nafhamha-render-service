# خدمة نفهمها: Remotion + YouTube

هذه الخدمة تحتاج خادم Docker منفصل؛ لا تعمل داخل استضافة لوحة التحكم. لا توجد مفاتيح أو حسابات مضافة مسبقًا. يوجد اتصال Google OAuth حقيقي، وتصدير Remotion حقيقي، ولا يتم نشر أي فيديو تلقائيًا دون طلب رفع من اللوحة.

## الإعداد من الموبايل
1. استخدم مزود استضافة يدعم Docker وخادمًا مستمرًا بذاكرة 2 GB على الأقل وقرص دائم. ارفع ملفات هذا المجلد إلى مستودع خاص أو عبر طريقة النشر التي يدعمها المزود. الحساب والتكلفة يحددهما المزود؛ لم يتم شراء أي استضافة.
2. انشر Dockerfile وأضف قرصًا دائمًا إلى `/data`. إنشاء الخدمة لا يمنحها حساب Google أو مفتاح Gemini تلقائيًا.
3. في إعدادات الأسرار أضف متغيرات `.env.example`. استخدم قيمتين عشوائيتين مختلفتين بطول 32 حرفًا أو أكثر لـ API_TOKEN وSESSION_ENCRYPTION_KEY. لا تضعهما في مستودع أو محادثة. احتفظ بمفتاح التشفير ثابتًا حتى لا تفقد القدرة على قراءة تفويض Google المحفوظ.
4. اضبط PUBLIC_URL على أصل HTTPS للخدمة، بدون شرطة أخيرة، وDASHBOARD_ORIGIN على أصل لوحة التحكم كما هو في الملف.
5. في Google Cloud: فعّل YouTube Data API v3، وأنشئ OAuth Client من نوع Web application. اضبط Authorized redirect URI إلى `https://YOUR-RENDER-SERVICE-HOST/oauth/google/callback` بدقة. أضف حسابك إلى مستخدمي الاختبار لو شاشة الموافقة في وضع Testing. اضبط Client ID وClient Secret في أسرار الخدمة.
6. افتح اللوحة من الموبايل، ثم «الربط»، وأدخل رابط الخدمة وAPI_TOKEN. اضغط «فحص الاتصال»، ثم «ربط حساب يوتيوب». اختر حساب القناة الصحيحة على شاشة Google. بعد العودة للوحة، أعد إدخال بيانات الجلسة وفحص الاتصال ليظهر اسم القناة.
7. في Gemini أنشئ مفتاحك من https://aistudio.google.com/apikey. أدخله في إعدادات جلسة اللوحة. يستخدم الخادم نموذج gemini-3.8-flash-tts بصوت Charon. قد تحتاج تفعيل فوترة أو صلاحيات نموذج حسب حساب Google. لا تُحفظ مفاتيح الجلسة في localStorage أو قاعدة بيانات. بديل إدخال المفتاح كل مرة: إعداد GEMINI_API_KEY كسرّ في استضافة لوحة التحكم عبر مديرها؛ هذه الخدمة لا تحتاج مفتاح Gemini.
8. اكتب الحلقة، ولّد الصوت أو ارفع تسجيلًا، وراجع الصوت. مدة التسجيل الفعلية هي مدة الفيديو؛ أزمنة المشاهد تُستخدم كأوزان نسبية لتوزيع المدة، وليست محاذاة تلقائية لكل كلمة. عدّل الأوزان عند الحاجة.
9. صدّر، راجع الفيديو، اختر العنوان والوصف والخصوصية وتصنيف الأطفال، ثم فعّل مربع المراجعة واضغط رفع. الافتراضي خاص. API يضع containsSyntheticMedia=true للفيديو المنشور من النظام. قد تؤثر سياسات Google وحالة مشروعك وحدود الاستخدام على الرفع والظهور؛ راجع YouTube Studio بعد الرفع.

## السلوك والحدود
- خدمة شخصية لمالك واحد وقناة واحدة، وليست منتجًا متعدد المستخدمين.
- جميع API محمية بمفتاح دخول، وCORS يسمح بأصل اللوحة وحده. OAuth يستخدم state وPKCE ومدة 10 دقائق.
- تفويض يوتيوب محفوظ مشفرًا AES-256-GCM في `/data/youtube.enc`، وليس في الواجهة أو ZIP.
- يسمح بثلاث مهام قيد التنفيذ/الانتظار وتصدير واحد في كل مرة. ملفات الصوت حتى 20 MB؛ مدة 2–240 ثانية؛ 1–12 مشهدًا.
- ملفات المهام تُحذف بعد 24 ساعة أثناء تشغيل الخدمة. قائمة المهام في الذاكرة؛ إعادة تشغيل الخدمة تفقد الوصول للمهام السابقة، لذلك نزّل الفيديو قبل إعادة تشغيلها. ملف OAuth يبقى على القرص الدائم. بعد إعادة التشغيل احذف ملفات jobs القديمة غير المطلوبة من القرص.
- التنزيل يتم عبر طلب مصادق عليه ثم ملف محلي في ذاكرة المتصفح. لا يعرض API ملف الفيديو بدون التفويض.
- مفاتيح الخدمة والجلسة تمسح من واجهة المتصفح عند إعادة التحميل. المسودة النصية فقط تبقى في localStorage على الجهاز.
- في حالة انقطاع الشبكة أثناء رفع يوتيوب، افحص القناة قبل إعادة المحاولة لتجنب النسخ المكررة. لا توجد إعادة نشر تلقائية.
- تصميم التصدير هو قالب موشن جرافيك تعليمي قابل لتعديل النصوص، وليس رسومات متخصصة يفهمها النظام تلقائيًا لكل موضوع.

## محليًا للمطور
يتطلب Node 22 وffmpeg ومتصفح Remotion:
```sh
npm ci
npx remotion browser ensure
# عيّن المتغيرات بأمان، ثم:
npm start
```
الاختبارات: `npm test`. راجع ترخيص Remotion وفق استخدامك: https://www.remotion.dev/license

## إعداد Google من لوحة الموبايل
بدل إدخال GOOGLE_CLIENT_ID وGOOGLE_CLIENT_SECRET في Railway، يمكنك إدخالهما في قسم الربط داخل الاستوديو بعد تشغيل الخدمة. احفظ الإعداد، ثم اربط حساب يوتيوب. يحفظ الخادم بيانات العميل مشفرة في /data/google-client.enc بنفس مفتاح التشفير الثابت. لا يُرجعها API ولا يسجلها. العميل من نوع Web application، وعنوان إعادة التوجيه هو PUBLIC_URL متبوعًا بـ /oauth/google/callback.
